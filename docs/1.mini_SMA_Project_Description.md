# Tài liệu Phân tích Dự án: Mini SMA (Smart Manufacturing Agentic AI)

**Người lập:** Business Analyst (AI)
**Phương pháp luận:** Top-Down (Từ tổng quan cơ bản đến chi tiết kiến trúc nâng cao)
**Mục tiêu:** Xây dựng một hệ thống phần mềm quản lý sản xuất thông minh (SMA) thu nhỏ, tích hợp đầy đủ công nghệ lõi (Tech Stack) giúp người học nắm bắt toàn bộ luồng dữ liệu, trước khi áp dụng các giải pháp mở rộng (Scaling) và kiến trúc phức tạp.

---

## 1. Tổng quan Dự án (Project Overview)
Dự án **Mini SMA** là một phiên bản dự án độc lập, thu gọn cốt lõi của hệ thống Smart Manufacturing Agentic AI. Dự án được thiết kế theo lộ trình 4 giai đoạn, giúp đội ngũ phát triển làm quen và tích hợp nhuần nhuyễn các công nghệ từ cơ bản (CRUD) đến nâng cao (RAG, IoT Telemetry, Neo4j Graph).

### 1.1 Tech Stack (Công nghệ sử dụng)
*   **Database (Lưu trữ kép):** PostgreSQL (Relational & Vector), Neo4j (Knowledge Graph), TimescaleDB (Time-series).
*   **Backend (Logic & API):** Node.js (Express), Prisma hoặc Sequelize ORM.
*   **Frontend (UI/UX):** React/TypeScript, Chart.js/Recharts.
*   **AI/RAG:** `pgvector`, LLM API (OpenAI/Gemini/Local model), Agentic UI.
*   **IoT/Hardware:** Vi điều khiển (ESP32/Arduino) hoặc Mock Script, MQTT/HTTP.
*   **Data Pipeline & CDC:** Debezium, Redis Streams/Kafka, Docker.

## 2. Phân tích Yêu cầu & Lộ trình Triển khai Chi tiết

### Giai đoạn 1: Khởi tạo CRUD & Luồng Dữ Liệu Cơ Bản (Tuần 1 - 2)
*Mục tiêu: Hiểu rõ luồng dữ liệu truyền thống từ Database -> Backend -> Frontend mà chưa cần xử lý các nghiệp vụ phức tạp.*

*   **Database (PostgreSQL Local):**
    *   Cài đặt trực tiếp PostgreSQL bản Local để dễ dàng thao tác.
    *   **Schema cốt lõi:** Thiết kế một database duy nhất với 2 bảng quan hệ cơ bản là `Products` (Sản phẩm) và `WorkOrders` (Lệnh sản xuất).
*   **Backend (Node.js/Express/ORM):**
    *   Khởi tạo project, thiết lập **Cấu trúc thư mục chuyên nghiệp (Production-ready)** ngay từ đầu: phân chia rõ ràng các tầng (Layered Architecture) như `routes`, `controllers`, `services`, và `models`.
    *   Cấu hình các Entity (Prisma/Sequelize) ánh xạ trực tiếp 1-1 với 2 bảng DB trên.
    *   Xây dựng các RESTful API cơ bản (GET, POST, PUT) tuân thủ chuẩn REST, áp dụng Dependency Injection cơ bản và tổ chức code thành từng module.
*   **Frontend (React/TypeScript):**
    *   Tạo một giao diện **Dashboard tĩnh** với Sidebar điều hướng cơ bản.
    *   Tích hợp API từ Backend: Hiển thị danh sách Lệnh sản xuất lên một bảng (`Table`) và tạo một `Form` cơ bản để nhập Lệnh sản xuất mới.

### Giai đoạn 2: Trợ Lý AI & Retrieval-Augmented Generation - RAG (Tuần 3 - 4)
*Mục tiêu: Đưa AI Agent vào luồng nghiệp vụ thực tế, giới thiệu khái niệm Vector Search và RAG thông qua một Agent duy nhất thay vì một hệ thống Multi-Agent phức tạp.*

*   **Vector Storage (PostgreSQL):**
    *   Kích hoạt extension `pgvector` trực tiếp trên Postgres hiện tại.
    *   Tạo thêm một bảng `KnowledgeDocuments` với cột chứa dữ liệu kiểu Vector (embedding).
*   **Data Ingestion Pipeline:**
    *   Viết một script nhỏ nhận tài liệu đầu vào (VD: Sổ tay vận hành máy định dạng PDF).
    *   **Logic:** Chunking văn bản (cắt nhỏ) -> Sử dụng API (OpenAI/Gemini) để chuyển thành số (embedding) -> Lưu trữ vào bảng `KnowledgeDocuments`.
*   **Frontend (Agentic UI):**
    *   Xây dựng module **Chatbox** trên giao diện React.
    *   **Luồng xử lý (Hybrid Search):** Khi người dùng đặt câu hỏi, Backend sẽ tìm kiếm các đoạn văn bản liên quan nhất trong Database, đẩy ngữ cảnh (Context) đó cho AI Agent xử lý và trả câu trả lời (Grounded Output) về màn hình Chatbox.

### Giai đoạn 3: Thu Thập Dữ Liệu Thiết Bị - IoT Telemetry (Tuần 5)
*Mục tiêu: Kết nối phần mềm với thế giới vật lý, xây dựng luồng dữ liệu thời gian thực (Real-time IoT) giúp hệ thống giám sát tình trạng máy móc sản xuất.*

*   **Hardware (ESP32/Arduino hoặc Mock Script):**
    *   Lập trình mạch vi điều khiển đơn giản gắn cảm biến nhiệt độ.
    *   Nếu không có phần cứng: Viết code sinh số liệu ngẫu nhiên (Mock) giả lập độ rung của máy tiện.
*   **Data Ingestion (Backend):**
    *   Cấu hình vi điều khiển gửi dữ liệu liên tục qua giao thức HTTP POST hoặc MQTT về Backend Java.
    *   Backend ghi nhận và lưu trữ dữ liệu thô vào cơ sở dữ liệu.
*   **Frontend (Data Visualization):**
    *   Sử dụng các thư viện biểu đồ cơ bản (Recharts/Chart.js) vẽ đường biểu diễn trạng thái (nhiệt độ, độ rung) theo thời gian thực.

### Giai đoạn 4: Đánh Giá & Nâng Cấp Kiến Trúc (Tuần 6+)
*Mục tiêu: Chỉ khi 3 giai đoạn trên chạy hoàn hảo, tiến hành đưa các công nghệ "hạng nặng" vào để giải quyết các nút thắt về kiến trúc và mở rộng hệ thống.*

*   **Containerization:** Chuyển đổi toàn bộ hệ thống lưu trữ từ cài đặt Local sang kiến trúc **Docker**.
*   **Kiến trúc Đồ thị (Knowledge Graph):**
    *   **Nút thắt:** Việc truy vấn quan hệ giữa Sản phẩm, Vật tư và Lệnh sản xuất trên CSDL quan hệ trở nên quá phức tạp và chậm.
    *   **Giải pháp:** Bắt đầu cài đặt **Neo4j** và dùng **Debezium (CDC)** để bắt sự kiện đồng bộ dữ liệu.
*   **Xử lý Dữ liệu Lớn (Big Data IoT):**
    *   **Nút thắt:** Khi dữ liệu cảm biến đổ về hàng triệu dòng làm chậm hệ thống đi đáng kể.
    *   **Giải pháp:** Thay đổi bảng lưu trữ sang **TimescaleDB** tối ưu cho time-series.
*   **Advanced AI Agent / API Orchestrator (2-Step Query):**
    *   Bắt đầu hoàn thiện các chức năng nâng cao (Multi-Agent, Audit Log, HITL Workflow) giống lộ trình bản SMA đầy đủ.
